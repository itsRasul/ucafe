# Trial lifecycle implementation report — 2026-10-05

## Discovery and plan

Existing: explicit trial start and stored UTC dates, immediate unpaid expiry without grace, verified-payment conversion, paid renewal/proration/downgrades, public suspension, service feature checks, encrypted SMS outbox and owner selection. Partial: trial entitlements used the selected plan, some admin endpoints lacked feature gates, locked navigation was hidden, and access projections became stale. Missing: trial SMS reminders.

The implementation extends those mechanisms in this order: canonical duration, effective trial entitlements, API gates, shared locked UX, outbox reminders/rechecks, tests and live verification. No duplicate billing, notification or entitlement system was introduced.

## Completion report

1. **Old duration:** The selected plan's editable `trialDays`, defaulted/seeded to seven days. Individual administrator settings and stored trial dates could differ; there was no immutable universal seven-day policy.
2. **Original definition:** `SubscriptionPlan.trialDays`, catalog migrations, and `SubscriptionsService.startTrial` using `addDays(now, plan.trialDays)`.
3. **30-day change:** `trial-policy.ts` is the runtime source of truth. Trial creation and the entity default use `TRIAL_DAYS=30`; plan updates reject other initial-trial durations. The migration normalizes catalog duration/default.
4. **Trial entitlements:** Central `entitlementState` resolves current Golden feature data during `TRIALING`. Feature checks, Admin access and the virtual trial card reuse it. The selected future paid plan remains unchanged; no Golden feature list is hard-coded.
5. **Expiry:** Existing effective-status calculation denies access at `now >= trialEndsAt` without a paid period, independent of timers/frontend state. Trials receive no paid grace. Paid subscription grace remains unchanged.
6. **Backend enforcement:** Existing service checks remain. A reusable feature guard also gates tenant Menu, Site, Promotions, Orders and Reservations controllers, including reads/media. Denials retain 403 / `FEATURE_UNAVAILABLE` and add an access reason. Public expiry preserves 423 / `TENANT_SUSPENDED`.
7. **Admin locking:** Authorized sections remain visible. Navigation reloads server access and opens one native dialog for trial expiry, expired/missing subscription, or plan exclusion. Direct locked routes show a shell fallback; API feature denials open the same dialog. Access refreshes on focus/every 30 seconds. A feature denial after token refresh no longer incorrectly signs out. The CTA uses `/admin/subscription`. Login, overview, billing and support keep their existing permissions.
8. **Existing SMS:** Paid 3/2/1-day, last-day, expiration, +3-day follow-up, payment success and failed-verification messages existed. Trial reminders did not.
9. **Added SMS:** `TRIAL_EXPIRING_7_DAYS`, `TRIAL_EXPIRING_2_DAYS`, `TRIAL_EXPIRED`, `TRIAL_EXPIRED_FOLLOW_UP`, through the existing sms.ir verify provider/outbox. Templates use `cafeName`; suggested Persian copy is in `NOTIFICATIONS.md`.
10. **Duplicate protection:** Keys combine event, subscription, exact stored trial boundary and owner ID. Existing unique/conflict-safe insertion protects repeat discovery/restarts; conditional pending-to-processing claims protect competing replicas. Tests exercise durable discovery deduplication and concurrent dispatchers. Lost provider responses remain an existing retry ambiguity.
11. **Payment suppression:** Discovery excludes converted trials. Delivery reloads committed paid entitlement, boundary, cancellation, tenant lifecycle and current owner user/membership/phone. Payment before expiry/follow-up invalidates queued messages. Pending/failed checkout grants nothing. Delayed verification retains the existing committed-payment authority.
12. **Compatibility:** Active and expired historical dates remain unchanged; no old trial reopens. Existing active trials use Golden configuration until their original boundary. Paid dates/plans/grace stay untouched. Historical SMS older than seven days after expiry is not discovered.
13. **Migration:** `1791200000000-ThirtyDayTrialPolicy.ts`, applied successfully locally, updates catalog duration/default only. Its down migration restores the old default but cannot reconstruct previous administrator-specific catalog lengths; tenant history is never rewritten.
14. **Tests:** New unit/PostgreSQL trial specs cover 30-day dates, selected-plan preservation, dynamic Golden flags, exact expiry, paid-plan access, direct guard rejection, all reminder windows, deduplication and conversion/recipient suppression. Existing feature/config fixtures were updated. Notification tests cover competing claims.
15. **Verification:** Workspace `npm run typecheck` and root `npm run build` passed; the final web build passed again. Final API `npm test` in Docker: 246 passed, 35 optional integrations skipped, with trial/public-purchase PostgreSQL integration enabled. This test run used transpile-only loading with independent strict typechecks. Web `npm test`: 29 passed. Earlier runs caught outdated fixtures, which were fixed and rerun. Migration run and `git diff --check` passed. Live active trial APIs returned 200; expired admin features 403 with `TRIAL_EXPIRED`, billing/access 200, public Menu/Site 423. Desktop/375px UI checks passed for Persian RTL copy, overflow, Escape/focus restoration, existing billing CTA and distinct paid-plan feature wording. Browser error logs were empty after successful verification. Disposable café/user/session/challenge fixtures and scripts were removed. There is no lint command. The existing Sentry config-import deprecation warning remains.
16. **Deployment/business limits:** Configure four numeric sms.ir template IDs before enabling the real provider; startup requires them. Real provider/template acceptance still needs external credentials. Pre-expiry messages have one-day catch-up windows; expiry is `[end,end+3d)`, follow-up `[end+3d,end+7d)`. Stale windows are discarded. The current tenant model has no independent administrative suspension reason; expired lifecycle-suspended tenants remain eligible for expiry/follow-up, suspended active trials are excluded. Payment can commit after the final eligibility read; SMS cannot be recalled. Provider acceptance with a lost response is not exactly-once delivery.

## Onboarding boundary

Platform/CLI provisioning still creates a draft; Platform Admin explicitly starts its trial. Public purchase still activates only after verified payment and does not start a free trial. Automatically enrolling every draft/public purchase would change the documented commercial onboarding contract and requires a deliberate separate decision. Every trial started through the existing trial service now lasts 30 days.
